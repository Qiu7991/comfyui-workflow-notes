# 低显存配置

> 在消费级显卡上跑 MiniMax H3 图生视频，三重补丁分别解决三个不同的显存峰值。

## 为什么需要补丁

MiniMax H3 是带音频分支的视频模型，一次推理要同时加载：

- UNET（`fl2va_pruned_int8_convrot`）
- 视频 VAE（`fp16`）
- 音频 VAE（`fp32`）
- 采样中间张量（随分辨率和帧数增长）

直接跑会 OOM。三重补丁不是「优化」，是「能不能跑」的前提。

## 三个补丁各解决什么

### SageAttention

```yaml
MiniMaxH3MemoryEfficientSageAttentionPatch: 启用
```

**解决**：注意力计算时的中间张量峰值。

标准 attention 需要物化完整的 `seq_len × seq_len` 注意力矩阵。视频的 token 数远大于图像（帧数 × 每帧 patch 数），这个矩阵会瞬间吃掉大量显存。SageAttention 用分块 + 低精度累加避免完整物化。

### ChunkFeedForward

```yaml
MiniMaxChunkFeedForward: 启用
chunk: 4
dim: 4096
```

**解决**：FFN 层一次性加载全部通道。

Transformer 的 FFN 会把 `dim` 扩展到 4 倍左右再压回来。`chunk=4` 表示把 FFN 的中间维度切成 4 块依次计算，峰值显存降到 1/4，代价是少量额外调度开销。`dim=4096` 要和模型的 hidden dim 对齐，填错会直接报维度不匹配。

### LowVRAMAttention

```yaml
MiniMaxLowVRAMAttention: 启用
chunk: 10
```

**解决**：注意力分块执行，进一步降低单块显存。

和 SageAttention 是互补关系：SageAttention 优化的是「矩阵怎么算」，LowVRAMAttention 优化的是「一次加载多少」。`chunk=10` 是实测下来的平衡点，再小会明显变慢。

## 量化选择

| 格式 | 精度损失 | 显存 | 适用 |
|---|---|---|---|
| `fp16` | 无 | 最大 | 显存充足时 |
| `fp8_scaled` | 小 | 中 | 四视图工作流用这个 |
| `int8_convrot` | 较小 | 小 | 生产默认 |

`int8_convrot` 的 conv-rot（旋转量化）比朴素 int8 精度损失小，因为它在量化前对权重做了 Hadamard 旋转，把离群值摊平。实测在 H3 上画质差异肉眼不明显，但显存省一半。

## 4-step Turbo LoRA

```yaml
LoRA:      minimax_h3_fl2v_lightx2v_turbo_4step_v0.1_comfy.safetensors
LoRA强度:  0.75
步数:      4
采样器:    res_multistep
调度器:    simple
```

### 为什么强度是 0.75 不是 1.0

Turbo LoRA 通过蒸馏把采样步数从几十步压到 4 步。代价是：

- 运动幅度衰减（人物动作变保守）
- 细节扁平化（皮肤、织物纹理变糊）

强度 1.0 时动作明显僵硬，像定格动画；0.6 以下又会出现运动不连贯。**0.75 是实测动作崩坏率最低的点**。

### 为什么采样器是 res_multistep

4 步采样对采样器很敏感。`euler` 在 4 步下会出现明显阶梯感，`res_multistep` 的多步残差修正能在极少步数下保持平滑。调度器配 `simple` 即可，其他调度器在 4 步场景下收益不明显。

## 首轮参数

```yaml
首轮比例:  9:16
首轮倍率:  0.7
帧率:      24 fps
超分:      关闭
```

**倍率 0.7** 是「先看清再放大」策略：首轮低倍率出片快、显存低，用来检查人物、手部、道具、动作、声音、口型。只有通过检查的镜头才值得用高倍率重跑或做后期放大。

**超分首轮关闭**：RTXVideoSuperResolution 会额外吃显存，且会掩盖生成阶段的问题（比如手指畸形被超分「修」成另一种畸形）。

## 常见故障对照

| 现象 | 可能原因 | 处理 |
|---|---|---|
| OOM | 三个补丁有任一未启用 | 检查三个 patch 节点是否都在启用状态 |
| 彩纹 / 花屏 | 用了实验版工作流或 VAE 不匹配 | 换回 `05-h3-i2v-lowvram.json` |
| 动作僵硬 | LoRA 强度过高 | 从 1.0 降到 0.75 |
| 动作漂移 | 倍率过高或种子不稳定 | 降到 0.7，固定种子再试 |
| 背景跟着人漂 | 关键帧本身有问题 | 回查图像阶段的双图编辑提示词 |
| 人物脸崩 | 未使用角色参考图 | 走「角色一致性方案」的三段式流程 |
